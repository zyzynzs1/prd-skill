# 代码分析指南（code-analysis-guide）

> 本文件中的引用路径均相对技能根目录（SKILL.md 所在目录）。

> **何时读取**：SKILL.md 阶段 1「功能盘点」开始前必读。

本指南解决一个问题：**如何从一份陌生代码仓库中，系统、可追溯地提取出产品功能清单**，作为 PRD 的依据。核心原则：先找入口，再顺藤摸瓜，每条功能留下代码证据。

## 1. 目标与产物

- 产物：`功能盘点-{产品/模块}.md`（中间产物，供用户确认功能范围，也是 PRD 的证据底稿）。
- 完成判据：每个子功能都登记了 `文件路径:行号` 或明确的符号名（路由名、组件名、接口路径、表名）；无法追溯的内容进【待确认】。
- 盘点结果是 PRD 第 7 节功能清单与第三部分正文的唯一来源，禁止在起草阶段临时新增未盘点的功能。

## 2. 扫描顺序（按信息密度从高到低）

| 步骤 | 扫描对象 | 提取什么 | 典型文件 |
|------|----------|----------|----------|
| 1 | README / 产品文档 / 原型说明 | 产品定位、模块名词表、已有功能描述 | `README.md`、`docs/` |
| 2 | 构建与依赖配置 | 技术栈、框架版本、第三方能力（地图、支付、IM、AI 等） | `package.json`、`pom.xml`、`go.mod`、`pyproject.toml`、`requirements.txt` |
| 3 | 路由 / 菜单 / 导航配置 | 功能骨架：页面清单、层级、入口 | `router/`、`routes.*`、`menu.*`、`app.json`、`pages.json` |
| 4 | 权限与角色配置 | 角色、权限点、按钮级权限 | `permission.*`、`auth/`、`roles.*`、`*.guard.ts`、后端 `@PreAuthorize` |
| 5 | 页面与组件 | 页面区域、字段、按钮、交互、校验、提示语 | `pages/`、`views/`、`components/`、`*.vue`、`*.tsx` |
| 6 | 接口定义 | 数据字段、分页/筛选/排序参数、导入导出、限制 | `api/`、`controller/`、Swagger/OpenAPI、`*.proto`、GraphQL schema |
| 7 | 数据模型与迁移 | 实体、枚举、状态机、字段长度与约束 | `models/`、`entity/`、`migrations/`、`schema.prisma`、建表 SQL |
| 8 | 状态管理 / 文案 / 定时任务 / 消息 | 跨页状态、提示语原文、异步能力、推送 | `store/`、`i18n/`、`locales/`、`cron/`、`jobs/`、`mq/` |

> 大仓策略：不要逐文件通读。先用 `glob` / `grep` 建立页面与接口清单，再只精读与功能相关的文件；目标是覆盖全部入口，而非理解全部代码。

## 3. 常见技术栈的入口识别

| 类型 | 入口线索 | 注意 |
|------|----------|------|
| 前端 SPA（Vue/React） | `router` 配置、`pages/`、`views/`、菜单常量 | 路由 `meta.title` 往往就是菜单名；懒加载路由也要统计 |
| 后端服务 | Controller/Router 注解、Swagger 文档、API 前缀 | 区分「供前端调用」与「内部/运维接口」，后者不写进 PRD |
| 移动端 / 小程序 | `app.json`、`pages.json`、页面目录、TabBar 配置 | TabBar 与二级页面要分别记录 |
| 管理后台模板 | 菜单配置、权限指令（如 `v-hasPermi`） | 按钮级权限是「使用角色」章节的直接依据 |
| 低代码 / 配置化 | 页面 schema、表单 JSON、流程定义 | 功能由配置决定，需读配置而非框架代码 |
| 定时任务 / 集成 | 任务表、调度配置、Webhook | 若无用户界面，归入「后台能力」，在 PRD 中说明触发时机与影响 |

## 4. 从代码到产品语言的翻译规则

| 代码里看到的 | PRD 中应写成 | 不要写成 |
|--------------|--------------|----------|
| `v-if="status === 1"` 显示编辑按钮 | 仅「草稿」状态的记录可编辑，其他状态不显示编辑入口 | 当 status 为 1 时 v-if 渲染按钮 |
| `@click="handleSubmit"` | 点击【提交】按钮后…… | 绑定 click 事件调用 handleSubmit |
| `axios.get('/api/order/list', {page, size})` | 订单列表按页加载，默认每页 20 条，支持翻页 | 调用 GET /api/order/list 接口 |
| `rules: { name: [{max: 50}] }` | 名称最多 50 字，超出无法输入 | 表单校验 max=50 |
| `watch: { keyword: debounce(300) }` | 输入关键词后 300ms 自动搜索，无需点查询 | 监听 keyword 做防抖 |
| `role: ['admin']` | 仅管理员可见 | 路由 meta.role=admin |
| `setTimeout(() => toast.hide(), 3000)` | 提示 3 秒后自动消失 | 3 秒后 hide toast |

原则：**保留用户可感知的行为与规则，去掉实现手段**。需要保留的技术信息（字段长度、状态枚举、接口限制）一律转成产品约束。

## 5. 功能盘点表结构

文件头部写清：仓库名、分析提交（commit hash）、分析日期、覆盖范围、未覆盖范围。

| 序号 | 功能模块 | 大功能点 | 子功能 | 代码证据 | 置信度 | 建议迭代 | 备注 / 待确认 |
|------|----------|----------|--------|----------|--------|----------|----------------|
| 1 | 科目管理 | 科目配置 | 科目列表 | `src/views/subject/List.vue:1`；`src/api/subject.ts:12` | 高 | 迭代1 | 无 |
| 2 | 科目管理 | 科目配置 | 科目配置弹窗 | `src/views/subject/ConfigDialog.vue:28` | 中 | 迭代1 | 【待确认】参数分组字段含义 |
| 3 | 作答 | 在线作答 | 开始作答 | `src/views/exam/Answer.vue:56`；`src/api/exam.ts:31` | 高 | 迭代1 | 无 |

列定义：

- **功能模块**：业务域（如「科目管理」「作答」「成绩」），与 PRD 第 7 节「功能模块」列一致。
- **大功能点 / 子功能**：与 PRD 第三部分标题层级一一对应；大功能点数量建议 3–10 个，子功能 1–6 个。
- **代码证据**：`相对路径:行号`，多个用「；」分隔；至少 1 条，优先给入口与核心逻辑。
- **置信度**：高 / 中 / 低，判定见第 6 节。
- **建议迭代**：结合优先级与依赖关系给出，最终以用户确认为准。
- **备注**：异常、权限、外部依赖、待确认问题。

## 6. 置信度判定与【待确认】

| 置信度 | 判定条件 | 处理方式 |
|--------|----------|----------|
| 高 | 路由/菜单 + 页面实现 + 接口/数据模型三者齐全 | 可直接写入 PRD |
| 中 | 只有路由或页面，缺少接口/数据依据，或仅有部分交互 | 写入 PRD，细节处标【待确认：待补信息/确认人】，Word 中红色显示 |
| 低 | 仅从代码片段、注释、TODO、废弃分支推测 | 默认不写入正文；确需写入时标【待确认】并说明依据 |

以下情况必须标【待确认】而不是猜测：业务指标与目标、角色职责边界、迭代时间、上线范围、外部系统对接协议、合规要求、截图（无法获取时）、数值型限制（代码中无明确来源时）。

## 7. 边界：哪些不算产品功能

- 纯技术设施：日志、监控、CI/CD、单元测试、构建脚本。
- 内部运维接口、调试接口、临时开关（除非用户明确要求写进 PRD）。
- 死代码、注释掉的模块、未挂载路由的组件。
- 第三方库自带能力（只写「支持 XX 能力」的结果，不写库实现）。
- 代码中不存在、仅凭行业惯例想象的功能。

## 9. 与 PRD 的映射

| 功能盘点 | PRD 位置 |
|----------|----------|
| 功能模块 + 大功能点 + 子功能 | 模板 一、7 功能清单、一、8 功能框架图、三、功能详细描述正文标题 |
| 建议迭代 | 模板 一、9 迭代规划、各功能「迭代版本」字段 |
| 角色与权限 | 模板 一、6 使用角色、功能「限制条件」 |
| 待确认清单 | 盘点阶段记录；起草时逐条内联写入 PRD 正文对应位置，Word 中红色显示（不设附录 A 汇总表） |

映射必须双向一致：功能盘点中的每一条子功能在 PRD 中恰好出现一次，PRD 中不得出现盘点之外的功能。

## 10. 常见错误

1. 只按目录结构罗列文件，没有归并成「大功能点 / 子功能」。
2. 证据只写文件名不写行号，无法复核。
3. 把技术实现直接抄进功能描述（见第 4 节翻译规则）。
4. 遗漏隐藏入口：按钮级入口、Tab 页签、抽屉、右键菜单、快捷键、批量操作。
5. 把废弃代码、内部接口当成产品功能。
6. 置信度全是「高」，实际上多处靠猜。
7. 盘点后不与用户确认就直接写完整 PRD，导致返工。
