# 功能点字段规范（field-spec）

> 本文件中的引用路径均相对技能根目录（SKILL.md 所在目录）。

> **何时读取**：SKILL.md 阶段 4「分迭代起草」开始前必读；每写完一个大功能点后复查一遍。

本文件规定「功能点描述规范」的完整写法，比 SKILL.md 第 5 节更细。所有功能点统一采用「大功能点标题 + 两列表格」的呈现方式：功能点以一级编号标题引领，其下用两列表格逐行呈现各子功能，左列为原型展示图，右列为该子功能的完整字段集。仅含一个子功能的功能点同样使用此格式（表格仅一行）。

## 1. 两列表格结构

- 表头固定为「原型展示图｜功能描述」，不得增删列。
- 每个子功能占一行；一行内用 `<br>` 分隔字段，字段标签加粗。
- 左列：该子功能核心操作界面的真实截图占位，每个子功能至少 1 张，禁止复用。
- 右列：字段 1–9 按固定顺序书写，缺一不可。

## 2. 九个字段的写法

| 序号 | 字段 | 写法要求 | 常见错误 |
|------|------|----------|----------|
| 1 | 功能点标题 | 子功能编号在大功能点下顺延（1.1、1.2……），居中、加粗，位于右列首行 | 编号与功能清单不一致；忘记加粗居中 |
| 2 | 更新时间 | `yyyy-mm-dd hh:mm:ss`（24 小时制），左对齐，另起一行；只在该功能实际改动时更新 | 格式写成 `2026/10/26`；批量刷新无关条目 |
| 3 | 优先级 | P0/P1/P2，红色加粗，左对齐另起一行。P0 = 阻塞主流程或核心合规；P1 = 重要但非阻塞；P2 = 体验优化 | 全部标 P0；与测试用例优先级不一致 |
| 4 | 迭代版本 | 如「迭代1」，左对齐另起一行 | 写版本号而非迭代号 |
| 5 | 任务规划 | `yyyy-mm-dd——yyyy-mm-dd`，左对齐另起一行 | 使用 `-` 或 `~` 连接；缺结束日期 |
| 6 | 功能描述 | 标签加粗；内容另起一行；说明使用场景、使用人、解决什么问题；**≤150 字** | 超字数；写成操作步骤；出现「强大的」「一站式」等营销词 |
| 7 | 核心流程 | 标签加粗；内容另起一行；用「 → 」从入口到完成串联操作步骤，每步一个原子动作；有分支时在主线后分条补充 | 用逗号串联；步骤过大（如「完成配置」）；遗漏弹窗/保存等关键节点 |
| 8 | 具体说明 | 穷尽式细化，编号 N. / N.M / N.M.K / N.M.K.L，逐级缩进 4/8/12 空格；按主题分组；写到原子粒度（见第 3 节） | 编号混用「①」「-」；只写静态布局；叶子条目仍让人追问细节 |
| 9 | 限制条件 | 权限、次数上限、前置条件、环境要求等；逐条编号；确无限制写「无」 | 留空；写「暂无」；把无关的设计规范塞进来 |

## 3. 「具体说明」细化标准

### 3.1 详尽的判定

每个叶子条目须达到「无需追问即可执行」：RD 读后可直接评估工时，UI 读后可直接绘制界面，QA 读后可直接编写用例。先用一句话检验——**这个条目会让读者产生「具体是什么样？点了会怎样？」的疑问吗？** 会，就必须继续向下细分；不会，就停，不要为凑层级而拆。

### 3.2 细化四步法

1. **列主题**：按用户使用路径或逻辑维度列一级条目（入口、页面组成、上传与文件列表、校验与提示、保存与回显、关闭、权限等）。
2. **拆动作**：每个主题下拆出用户可执行的动作与可见对象（按钮、字段、列表、状态、提示）。
3. **补三要素**：对每个可操作对象补齐交互后效果、作用范围、生效时机。
4. **收口检查**：逐条问「还有没有分支/异常/边界没写」，直到覆盖全部状态。

### 3.3 编号与缩进

- 一级「N.」，二级「N.M」，三级「N.M.K」，四级「N.M.K.L」，禁止其他编号形式。
- 一级顶格，二级缩进 4 个空格，三级缩进 8 个空格，四级缩进 12 个空格；同一层级缩进必须一致。
- 同级条目编号连续，禁止跳号；每个子功能的「具体说明」都从 1. 重新开始编号。

### 3.4 按类别查漏（按代码实际情况选取，不涉及则忽略）

| 类别 | 必写内容 |
|------|----------|
| 入口 | 从哪个菜单/页面/按钮进入；是否支持直接 URL 访问；入口的显示条件 |
| 页面组成 | 区域划分、标题、字段、操作按钮的清单与位置 |
| 按钮 | 名称、颜色、位置、样式（色块/超链接）；交互后效果（页面反馈 + 数据变化）；作用范围；生效时机 |
| 列表 | 字段名称与来源；超长截断与悬停；空数据展示；行内操作所在列与顺序；默认排序与表头排序；分页与筛选记忆规则 |
| 表单 | 控件形式、必填、字数/字符/格式限制、默认值；校验时机；提交成功/失败反馈；防重复提交 |
| 提示 | 提示类型（全局/弹窗）、提示语、淡出时间、成功/失败提示 |
| 数据 | 同步时间、导入导出的大小/格式限制、数据来源与刷新时机 |
| 交互状态 | 悬停、焦点、禁用、选中、加载中的视觉样式（颜色、透明度、指针）与可点性 |
| 跳转导航 | 跳转目标与方式（当前页/新标签页/新窗口/弹窗/抽屉）；返回后是否保留筛选、翻页、选中项 |
| 异常 | 每种异常触发条件与页面表现、提示语、数据是否回滚 |
| 权限 | 无权限时的入口隐藏/置灰/拦截方式与提示 |

### 3.5 交互三要素（凡涉及用户操作的组件必须写全）

1. **交互后效果**：点击后页面给出什么反馈（跳转/刷新/弹窗/提示），数据发生什么变化。
2. **作用范围**：作用于当前行、选中项、当前查询结果还是全部数据；是否影响关联数据（如删除科目后其下小题如何处理）。
3. **生效时机**：立即生效、二次确认后生效，还是需保存后生效。

## 4. 正确范例与反例

**反例（不合格：只有静态布局，无法执行）**

```text
1. 弹窗
   1.1 有名称输入框和保存按钮
   1.2 保存后关闭
```

问题：没说输入限制、校验、按钮状态、保存失败怎么办、关闭后列表是否刷新，RD/UI/QA 都无法开工。

**正例（合格：可估时、可出图、可写用例）**

```text
1. 入口与打开方式
   1.1 题目设置列表的「操作」列（固定右侧）第三项为「小题管理」文字按钮，点击后在当前页弹出「小题管理」弹窗，不跳转、不新开页面
   1.2 列表行状态为「已发布」时该按钮置灰不可点，悬停提示「已发布科目不可编辑小题」
2. 弹窗结构与默认态
   2.1 弹窗宽 720px、居中，遮罩透明度 0.45；标题「小题管理 - {科目名称}」居中加粗，右上角为关闭图标 X
   2.2 顶部为科目名称只读文本；中部为小题列表；底部「取消 / 保存」按钮右对齐，保存为主按钮（主色底白字）
   2.3 打开时默认选中第一个小题，若科目下无小题则列表区展示空状态插图 + 文案「暂无小题」+ 主按钮「新建小题」
3. 保存与反馈
   3.1 点击「保存」后按钮进入加载态（文案变为「保存中…」且不可重复点击），成功后 Toast 提示「保存成功」，弹窗关闭并仅刷新当前行数据并高亮 2 秒，不重置列表筛选与分页
   3.2 保存失败时弹窗不关闭，Toast 提示「保存失败，请重试」，已填写内容完整保留
   3.3 点击「取消」或右上角 X 时，若存在未保存修改，弹出二次确认「有未保存的修改，确定关闭？」；选择「取消」留在弹窗，选择「确认」关闭且丢弃修改
4. 校验与限制
   4.1 小题名称必填，为空时输入框下方红色提示「请填写小题名称」，且保存按钮拦截并定位到该项
   4.2 小题名称上限 50 字，超出部分无法输入，输入框下方灰色辅助文字「最多 50 字」
```

## 5. 每个子功能写完后的自检五问

1. 编号是否连续、缩进是否一致、层级是否超过四级？
2. 每个可点组件是否写了交互后效果、作用范围、生效时机？
3. 是否写了空数据、加载中、禁用、异常四类状态？
4. 列表/表格是否写了排序、分页、筛选、超长与空态？
5. QA 能否只凭本段写出用例？写不出说明还缺细节。
